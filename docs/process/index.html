Build with AI, the way this was built

Every release in this repository was drafted with AI and decided by a person. The AI builds; the person reads and types the decision at a gate; every push is sealed and timestamped; every release gets a DOI. The process is open: use it for your own work.

1. The loop

Intent. The person says what is wanted. The intention is the person's: the AI does not replace it with its own reading.
Payload. The AI builds the change and the tests that check it, and packs them with a script that carries its own gate.
Dry run. The script checks the live repository is where the change was built, applies it to a scratch copy, and runs the gate. Nothing is pushed.
PUSH, typed. The person reads what will change and types PUSH with a reason. That typed line is the recorded intent.
Receipt, timestamp, seal. A receipt of the decision is written and timestamped (OpenTimestamps); a manifest of every file's hash is rebuilt, verified and timestamped; old manifests and proofs are kept, never overwritten.
Contract check, push, return-to tag. The repository's own checks run once more; the commit is pushed; a tag marks a point anyone can return to.
MINT, typed. The person types MINT; misty deposits the release on Zenodo and a DOI is minted; the DOI is written back, resealed and pushed.

Gates refuse only on what the release needs: the expected base, the payload that was built, the repository's own tests and contract, no secrets, no oversized files, versions agreeing. Every other check reports and never refuses.

2. The rules: the master contract

Every repository follows the master contract in zistgah/governance; a repository may add to it and never relax it. Among its clauses:

ClauseIn short
C31Retrieve before assuming: what is in the repository beats what anyone remembers.
C37Never bluff: say what was verified, and how.
C38The intention is the author's; a claim that cannot be verified keeps its wording and carries a disclaimer beside it.
C39Gates guard the release, and nothing else.

Claims carry their evidence state (AyeKnow): defined, implemented, executed, measured, verified, reproduced, open.

3. Install

git clone https://github.com/zistgah/governance     # zops: ops/zops.sh, and the master contract
pip install misty-doi                                # misty: Zenodo deposits and DOIs (needs a Zenodo token)
pip install opentimestamps-client                    # ots: timestamps on receipts and manifests
# and the GitHub CLI, gh, from your system's packages

4. Use it: a seed in a dozen lines

. ops/zops.sh
zops_init "my project seed"
zops_preflight git python3 -- gh misty ots       # required -- optional
zops_repo my-org/my-project                      # clone or reuse; safe to rerun
zops_contract_begin
  zops_check Q1 "copyright"      zops_check_copyright
  zops_check Q2 "affiliation"    zops_check_affiliation
  zops_check Q3 "no placeholder" zops_check_no_placeholder
zops_contract_end || exit 1
zops_diff
zops_push "my-project: seed"                     # gate, commit, receipt, stamp, reseal, verify, push
zops_mark                                        # a return-to tag
zops_done

This is the usage in zops's own README. Worked examples in this repository: scripts/parashakti.sh (a parametric pipeline with a timed sanity check), the update scripts that publish each version, and the UISA seed script.

5. With any AI

Give your AI these instructions before the work, and hold it to them:

Retrieve before you write: read the repository and its contract first; never rely on memory for a fact you can check.
Build the change with its own tests, and a script with a dry run. Do not push or mint: I type PUSH and MINT.
Say exactly what you verified and how. Mark anything unverified, beside the claim. Never call done what I have not accepted.
Gates refuse only on what the release needs; every other check reports.
