Can a language survive the whole computing stack?

“I give my cloth to the tailor. After that I depend on whatever he stitches.”

A question asked in a language-technology discussion: Unicode is an agreement on which numbers mean which characters, but what happens to a character after that, inside processors, assembly, file formats, compilers and apps? Is there one model that lets a character of any script remain intelligible and controllable all the way down, and all the way back up?

This page answers by following one character. Choose any character, in any script; it travels down through every layer of the stack and comes back. Everything the page computes, it computes in your browser; everything marked as computed by Hindawi was computed by its real compilation pipeline when this site was built.

Human language → script → character → encoding → software → compiler → machine → firmware → debugging → hardware → physical signal

This is not only a Unicode question. It is a question about every layer the information passes through.

Where we mix everything up

The same information has many representations. A glyph is what a font draws; a character is the abstract letter; a code point is its number in Unicode; UTF-8, UTF-16 and UTF-32 are three ways of writing that number as bytes; hexadecimal and binary are two ways of writing the bytes for people.

Representation is not encoding

A four-bit value can be written with any sixteen symbols. Writing ten to fifteen as क ख ग घ ङ च instead of A B C D E F changes nothing in the bits. It changes only what a human reads.

Does a CPU understand Devanagari, Arabic or Han?

  
No script is required. Processors, microcontrollers and accelerators work on numbers: bits, instructions,
  memory and signals. A script enters at a human-facing layer: a font, an input method, a source file, a compiler that
  reads it. The question that matters is at which layer human notation is introduced, and who interprets it there.






  
Qwan-tum Tum Tum: from continuous to discrete

  
The cart moves continuously; the horse trots discretely: tum, tum, tum. A continuous signal is sampled,
  quantised into discrete levels, turned into states, and encoded. Binary is one choice of levels among many: balanced
  ternary uses −1, 0, +1; quinary −2 to +2; in general 2k+1 levels from −k to +k.

  

    

  
  

  
Gray code orders the states so that neighbouring levels differ in one bit. It does not compress;
  compression comes from giving frequent symbols shorter codes (average length Σ pᵢ·lᵢ, bounded below by the entropy H).






  
The 7-bit lab

  
Seven bits give 2⁷ = 128 states. Unicode does not fit in 128 states at once, but one segment of it can: a local
  alphabet. The 33 control positions stay as they are; an escape followed by a segment number switches into “our”
  alphabet, and Shift In returns to ordinary text. ISO/IEC 2022 used the same idea, escape sequences that designate a
  character set, decades ago. This is an experiment, defined and run in this page.

  

  
  

  

  






  
Romenagri and Hindawi: keeping the language all the way to the machine

  
Romenagri writes Indic scripts in 7-bit form with phonetic fidelity, and reverses back to the script. Hindawi uses it
  to compile programs written in a language: the script filter brings a script to a common form, Romenagri gives every
  native word a 7-bit form, and the language's transducer turns the keywords into the host language's; names keep
  their Romenagri form all the way into the binary's symbols. The computer never needed Latin; the toolchain did.
