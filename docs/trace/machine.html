From script to silicon: inside the machine

Follow an Indic character from the keyboard into numbers, through the algorithm that forms it, onto a text-mode screen, into graphics mode and the framebuffer, out through the DAC or a digital link to the pixels, and on into GPUs, GPGPU and AI. At every step the numbers are shown.

At this point, is the machine still dealing with a character, or only with numbers?

Processors (CPU, MCU, GPU, TPU) work only on numbers. A script is an encoding: people agree that certain numbers mean certain letters. Where a character is still a character, and where it becomes only numbers, is what this page shows.

2. APCISR: how the letters are formed

APCISR (2003 to 2006) renders Indic text in text mode, in software. It is based on a 9-grid theory for Brahmi-derived scripts: every component of a letter is described on a 3×3 logical grid, three levels (urdha above, madhya in the middle, nimna below) by three positions (matrik, lipik, purak). The grid is not a 3×3 bitmap: each of its nine cells holds a number naming a piece of a glyph.

As the ISCII bytes are read, the algorithm looks each component up in its table (its ISCII bytes, its Romenagri name, its purna and its nine grid values), then places the nine values into a growing working map, three rows by as many columns as the text needs, at positions decided by its state: the cursors matrik, lipik and purak, the purna of this and the previous component, and whether a halant or a ra with halant is waiting for what comes next. Values meet by bitwise OR. Rules then move or add pieces (the ra below, u and uu below, the ref above, visarga, anusvara, chandrabindu, the i that reaches back), empty columns are removed, and each cell's value is replaced by a font character.

3. Text mode: the screen holds numbers, the font gives the dots

In text mode the video memory holds, for each place on the screen, a character code and an attribute: 65 for A, and a byte for its colours. On a PC that memory starts at segment B800 (graphics modes use A000), mapped into the system's memory. Every frame the display adapter reads it, looks each code up in its font (on old adapters a font ROM), and lights the dots of that character's bitmap. The screen is redrawn many times a second: 60 times, or 144 on a gaming laptop's panel. Below is an 80 × 60 character screen. APCISR's line takes three text rows: urdha, madhya, nimna. A teletype or an early screen worked like a typewriter whose carriage only moves right: each character appears whole at the next place. Left-to-right writing suits it; a vowel sign above or below, or a conjunct, needs to come back to a place already written, and right-to-left scripts are drawn against the carriage. APCISR answers by composing each syllable in its working map first and writing it out complete, over three rows. Text-mode Indic renderers are still rare; the GIST card did this in hardware, APCISR in software, by different methods.

A terminal is an input device and an output device together. Clusters and supercomputers are often headless, in lights-out rooms, reached only from a remote terminal: the same text-mode ideas, without a screen attached.

4. Graphics mode: software draws the character

In graphics mode the video memory holds pixels, not character codes. The software carries the font (TrueType and the like) and draws each character into the pixels. A raster font is dots at one size; a vector font is the outline, which can be scaled up without jagged edges. Either way, every pixel's value is finally needed: turning outlines into dots is rasterisation.

5. The framebuffer: a grid of numbers

The framebuffer is the frame being displayed, held as numbers: one bit per pixel for black and white, or three numbers per pixel for colour, red, green and blue (RGB), often with a fourth (alpha). RGB is one colour space: any set of axes is a space. HSV is another. The same science of measuring colour is used to tell temperatures of objects and distances to galaxies. Tap a pixel.

6. To the display: a DAC, or a digital link

Analogue (VGA)

A digital-to-analogue converter turns each number into a voltage: in VGA, 0 to 0.7 volts on each of the red, green and blue wires.

Digital (HDMI, DisplayPort)

The numbers travel as numbers, in a serial digital stream; the monitor itself turns them into light. No DAC is needed in the computer.


  

  
Almost all displays today are raster displays, grids of pixels. A vector display draws lines
  directly; an analogue oscilloscope still does.






  
7. Why GPUs: many pixels, the same work

  
Rasterising means computing every pixel of every frame. A 1920 × 1080 screen has 2,073,600 pixels; at 144 frames a second
  that is about 299 million pixel values a second. One processor does them one after another; a graphics processor has many
  small processors doing them at once. Software rendering uses the CPU; hardware rendering uses the GPU.

  

  





  
8. GPGPU and CUDA: the same processors, other numbers

  
A frame is a matrix of numbers; so is much of science. From around 2007, with NVIDIA's CUDA, GPUs were offered for work
  that is not graphics: General-Purpose computing on GPUs. In CUDA a kernel is a function run by thousands of
  threads at once, grouped in blocks of a grid, on the GPU's CUDA cores. Below, each output of a
  matrix product is one thread.

GPU hardware, the CUDA programming model, GPGPU computation and AI workloads are four different
  things; each made the next possible.






  
9. AI: matrices all the way

  
A layer of a neural network is a matrix product followed by a simple function: y = f(W·x + b). Training and
  running a model is billions of such products, which is why the GPU's parallel numerical machinery accelerates AI. When one
  chip helps another do its work faster, we call it acceleration: the GPU accelerates the CPU, as the cores of a phone help
  each other.
